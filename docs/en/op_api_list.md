# Operator APIs (aclnn)

## How to Use

To make it easier to call operators, a set of C-based APIs (with the **aclnn** prefix) are provided. You do not need to provide the Intermediate Representation (IR) definition to facilitate efficient model and application development. This method is called single-operator API calling, or aclnn calling for short.

- **Header File/Library File**

  When calling operator APIs, you need to reference the dependency header file and library file. Generally, the header file is stored in `${INSTALL_DIR}/include/aclnnop` and the library file is stored in `${INSTALL_DIR}/lib64`. The specific files are as follows:

  - Header file: Method 1 (recommended): Reference the general header file aclnn\_ops\_\$\{ops\_project\}.h of the operator repository. Method 2: Reference the header file aclnn\_\*.h of a single operator API.
  - Library file: The library file libopapi_${ops_project}.so corresponding to the operator repository is referenced. Note that the original libopapi.so file of all operator repositories will be deprecated and is not recommended. It cannot be used together with a single operator repository file.

  ${INSTALL_DIR} indicates the file path after CANN installation. \$\{ops\_project\} indicates the operator repository name (such as math, nn, cv, and transformer). Change it to the actual operator repository name.

- **Version Evolution**

  Note that some APIs have multiple versions. Select the latest version. (APIs of a later version are compatible with all capabilities of an earlier version.)
